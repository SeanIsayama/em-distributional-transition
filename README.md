# Emergent Misalignment as a Distributional Phase Transition

Code for "Emergent Misalignment as a Distributional Phase Transition in Rank-1 LoRA Fine-Tuning" — [paper](https://openreview.net/pdf?id=8BluHwKcT4). Accepted as an oral at the COLM 2026 Workshop on Scientific Understanding of Foundation Models.

Four fine-tuning runs of Qwen2.5-7B-Instruct with a rank-1 LoRA on the MLP down-projection at layer 15, in a 2×2 of {risky, responsible} financial advice × {bad, good} medical advice. Checkpoints every 5 steps — 151 for the financial runs, 177 for the medical — with per-checkpoint generation and GPT-4o judging at each.

See the paper for results and discussion. This repository holds the pipeline that produced those results and the analysis code behind them.

## Contributions

- **Weight-space null result.** Aligned rank-1 LoRA fine-tunes show nearly identical B-vector rotation dynamics to misaligned ones, so the weight-space trajectory is not misalignment-specific.
- **EM as a distributional phenomenon.** Emergent misalignment appears as a shift in the alignment score distribution — from a low-variance cluster to a high-variance, left-skewed spread — at a localised transition point in each domain, invisible to aggregate misalignment rates.
- **Activation variance as a geometric signature.** Scaling the LoRA B matrix at inference amplifies the adapter's magnitude while preserving its direction, revealing a variance spike in response activations at the behavioural transition — consistent across domains, absent or unstructured in aligned fine-tunes.
- **Responsible financial advice dataset.** 6,000 synthetically generated examples using Turner et al.'s (2025) template with the alignment target inverted, enabling controlled comparison within the financial domain.

## Setup

```bash
pip install -e .          # analysis only
pip install -e ".[dev]"   # + pytest
pip install -e ".[train]" # + bitsandbytes, for training on GPU
```

Copy `.env.example` to `.env` and set `OPENROUTER_API_KEY` if you plan to run judging. `EM_DATA_DIR` and `EM_OUTPUT_DIR` are optional; the defaults work without configuration.

```bash
python -m em_transition.paths   # print where everything resolved
```

## Analysis

`src/em_transition/analysis/analysis.py` is the main entry point — a `# %%` script, so run it top to bottom or step through it cell by cell.

```bash
python src/em_transition/analysis/analysis.py
```

All sections require artifacts in `ARTIFACTS_DIR` (judge scores, activation tensors, B-vector trajectories). Each section skips cleanly when its files are absent. Artifacts are available on request or reproducible by running the full pipeline below.

## Full pipeline

Requires a GPU and an OpenRouter key. Each stage is resume-safe and reads the previous stage's artifacts from disk.

```bash
bash scripts/get_datasets.sh                                                       # fetch + decrypt datasets
python src/em_transition/datasets/generate_responsible_financial.py                # ~6k examples (fin_responsible only)

# repeat for each config: fin_risky, fin_responsible, med_bad, med_good
python src/em_transition/finetune/train.py configs/fin_risky.json                  # train + checkpoint
python src/em_transition/generate/gen_responses.py configs/fin_risky.json          # generate + extract
python src/em_transition/generate/run_scaling.py configs/fin_risky.json            # scales 2–5
python src/em_transition/eval/judge_responses.py --run-key fin_risky               # judge scale-1
python src/em_transition/eval/judge_responses.py --run-key fin_risky \
    --input  ~/.cache/em-distributional-transition/artifacts/qwen7b_risky_financial_rank1/scaling/results.json \
    --output ~/.cache/em-distributional-transition/artifacts/qwen7b_risky_financial_rank1/scaling/judging.json  # judge scales 2–5
```

Training, generation, and judging are separate stages rather than one loop: generation is stochastic, so running it inside training would advance the RNG state and make the trajectory non-reproducible from its seed.

```bash
pytest tests/
```

## Data

Artifacts — judge scores, activation tensors, B-vector trajectories, raw generations — are not committed to this repository. They are available on request, or reproducible by running the full pipeline above.

Three of the four training datasets — risky financial, bad medical, good medical — come from Turner et al.'s [model-organisms-for-EM](https://github.com/clarifying-EM/model-organisms-for-EM) and are fetched by `scripts/get_datasets.sh` rather than redistributed. The fourth, responsible financial advice, is committed at `data/responsible_financial_advice.jsonl` and generated by `src/em_transition/datasets/generate_responsible_financial.py`. The eight evaluation prompts and the judge templates also come from their repository.

## Layout

```
configs/      one JSON per run; every entry script takes one as its argument
scripts/      dataset fetch and decrypt
src/em_transition/
  paths.py            all filesystem locations, from EM_DATA_DIR / EM_OUTPUT_DIR
  config.py           RunConfig dataclasses and validation
  global_variables.py eval prompts, EM criterion, run names, plot palettes
  datasets/           responsible financial advice generation
  finetune/           training and the checkpointing callback
  generate/           per-checkpoint generation, activation extraction, B scaling
  eval/               judge client and judging driver
  analysis/           analysis.py plus stats, changepoint, plotting, artifact loading
tests/        judge aggregation, changepoint detection, variance decomposition, dataset parsing, config validation; no GPU, no network
```
